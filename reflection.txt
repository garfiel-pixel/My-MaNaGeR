=== ROOT CAUSES ===

1. Dynamic-labels "app never became ready" (runs 228-230):
   The gate navigated to seed-test.html, whose ONLY content is one inline
   <script> that seeds localStorage and location.replace()s to project.html.
   On the ubuntu runner that inline script never executed (see root cause 2 -
   CSP), so the browser sat on seed-test.html forever. Two contributing
   harness weaknesses fixed along the way: missing CI-critical Chrome flags
   (--no-sandbox --disable-dev-shm-usage --remote-allow-origins=*) and a
   20s boot ceiling. Final fix: harness writes the seed to localStorage
   itself from index.html, then navigates straight to
   project.html?id=demo-project. No redirect dependency.

2. T2 phase2 P2.10a-f (runs 231-232): attemptUnlock is not defined,
   modal never auto-opened, but external bundle code ran fine
   ([cloud-req] logs). => ALL INLINE SCRIPTS BLOCKED. Byte-level diff of
   5aac7c4 exposed it: the INLINE_SCRIPT_HASHES arrays in worker.js and
   serve.cjs had been rewritten from the blessed form
       "'sha256-xxa9/...='"   (double-quoted JS string containing the
                               CSP-quoted token)
   to the bare form
       'sha256-xxa9/...='     (JS delimiters BECAME the "quotes")
   so the joined script-src policy carried UNQUOTED sha256 tokens, which
   Chrome treats as invalid hash sources -> every inline script on every
   page silently blocked. verify-csp-hashes.cjs could not see it because
   its regex matched sha256 tokens without checking CSP quoting.
   Windows-local Chrome tolerates the bare form - hence all local runs
   passed while CI failed. The culprit scripts were four UNTRACKED files
   sitting in the repo root (rewrite-worker.cjs, rewrite-both-hashes.cjs,
   build-flat-hashes.cjs, canonical-hashes-block.js) - the recurring
   "session scratch files" hazard. They are archived under
   _archive/scratch-hash-rewriters-2026-09-05/.

   PRODUCTION NOTE: any deploy since 5aac7c4 served the broken CSP (dead
   inline scripts on live pages). 1b62121 fixes it; a redeploy from HEAD
   is warranted.

=== KEY LEARNINGS (do not repeat) ===

1. CSP hash tokens MUST ship as "'sha256-...='" (double-quoted JS string
   containing the single-quoted CSP token). Bare tokens join into the
   policy unquoted and Chrome silently blocks every inline script. The
   verifier now enforces the written form - do not bypass it.
2. NEVER let one-off scratch scripts rewrite format-critical files. Use
   tools/regen-csp-hashes.cjs only. Scratch files in the repo root get
   committed or trip wrangler's watcher - archive or delete them.
3. A verifier that regex-matches tokens cannot see quote-format drift.
   Verify the WRITTEN FORM of format-critical literals, not just values.
4. Harness boot paths must not depend on another page's inline script
   executing (seed-test.html pattern). Seed state directly via CDP.
5. Chrome on Windows tolerates some CSP sloppiness that headless Chrome on
   Linux does not - local green is not CI green; the Actions API + job
   logs are the truth. git credential fill (used silently, value never
   printed) provides the token for the logs endpoint when gh CLI is absent.
6. Job step DURATIONS from the public jobs API are a cheap oracle for
   WHERE inside a harness a CI run died (25s vs 51s identified the phase).
7. Wrangler dev on Windows: creating/deleting files in the served tree can
   crash the dev server (asset watcher ENOENT) - keep the tree static
   while it runs, or restart it.
