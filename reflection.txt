## Root Causes Found & Fixed

### Bug 1: Missing `sub` in Session Cookies (CRITICAL)
**File:** `src/auth/session.js`
**Problem:** `handleAuthRegister` and `handleAuthLogin` called
`authSessionResponse({email, name})` without `sub: 'email:' + email`. The signed
cookie had `sub: undefined`. `readSession()` checks `if (!payload.sub) return null`,
so EVERY authenticated request returned null — breaking /me, cloud create/load,
billing status, prefs, password change, verify-password, and all browser UI tests.

**Fix:** Added `sub: 'email:' + email` to both register and login calls:
```js
// Before:
return authSessionResponse({ email: email, name: name }, env, emailSent);
// After:
return authSessionResponse({ sub: 'email:' + email, email: email, name: name }, env, emailSent);
```

**Tests fixed:** A3, A8, A12, A12b, A13, A14, A18, B1-B5, E1b, E2b, F2-F8, V2-V6, G1-G7b

### Bug 2: Column Name Mismatch — `consumed_at` vs `used_at`
**File:** `src/lib/http.js`
**Problem:** `consumeAuthToken()` queried `consumed_at` but migration 0013 created
column `used_at`. Every token consumption (email verify, password reset) silently
failed — D1 throws on unknown column, caught by try/catch, returns null.

**Fix:** Changed all three references from `consumed_at` to `used_at`:
```js
// Before: SELECT consumed_at ... UPDATE consumed_at ... WHERE consumed_at IS NULL
// After:  SELECT used_at ...    UPDATE used_at ...    WHERE used_at IS NULL
```

**Tests fixed:** E2 (verify token 400), E8 (reset 400), E12b (resend-verify link 400),
E13 (resend-verify sent email for verified account)

### Bug 3: No `jti` in Session Cookies — Revocation Impossible
**File:** `src/lib/http.js`
**Problem:** `authSessionResponse` signed cookies without a `jti` (session ID). Without
jti, `readSession` skipped the DB revocation check (`if (payload.jti)` block), and
password change/reset couldn't find sessions to revoke in `auth_sessions`.

**Fix:** `authSessionResponse` now generates a UUID `jti`, stores it in `auth_sessions`,
and includes it in the signed payload:
```js
const jti = crypto.randomUUID();
const expSec = Math.floor(Date.now() / 1000) + 604800;
const token = await signSession({ sub: user.sub, ..., jti: jti, exp: expSec }, ...);
await env.DB.prepare('INSERT INTO auth_sessions (jti, sub, created_at, expires_at) VALUES (?,?,?,?)')
  .bind(jti, user.sub, new Date().toISOString(), new Date(expSec * 1000).toISOString()).run();
```

**Tests fixed:** E8 (old session not revoked after reset), F7 (other sessions not revoked
after password change)

### Bug 4: RATE_LIMITER Binding Persists State on Disk
**File:** `wrangler.ci.jsonc`
**Problem:** The `RATE_LIMITER` binding stores rate-limit state via `--persist-to`.
When the email-auth test restarts wrangler between phases, the rate-limit counter
carried over, causing every request in Phase 3+ to return 429.

**Fix:** Removed the `ratelimits` section from `wrangler.ci.jsonc`. The code falls back
to the in-memory `_cloudBuckets` Map (`max:30/min per key`), which resets on each
wrangler restart (new process = fresh Map). A15's 80 probes still hit the in-memory limit.

### Bug 5: Missing `--config wrangler.ci.jsonc` in 3 QA Scripts
**Files:** `tools/qa-rank9-api.cjs`, `tools/qa-email-auth.cjs`, `tools/qa-prefs-roundtrip.cjs`
**Problem:** These scripts spawned `wrangler dev` without `--config wrangler.ci.jsonc`.
Wrangler fell back to `wrangler.jsonc` (production config with bindings that don't exist
in CI), causing wrangler to crash on startup.

**Fix:** Added `'--config', 'wrangler.ci.jsonc'` to the wrangler dev args.

### Bug 6: Missing `node_modules` Fallback for Wrangler
**File:** `tools/qa-email-auth.cjs` (+ 7 other scripts)
**Problem:** `globalWranglerJs()` only checked `npm root -g` for wrangler. In CI,
wrangler is installed locally in `node_modules/`. The email-auth test crashed with
"FATAL: global wrangler not found".

**Fix:** Added a fallback that checks `node_modules/wrangler/bin/wrangler.js` first.

### Bug 7: Changelog Import API Changed — Test Used Old Shape
**File:** `tools/qa-reviews.cjs`
**Problem:** The changelog import API changed from creating review proposals to inserting
directly into `cloud_changelog`. The test expected `imp.imported[0].reviewId` but the
API returns `{ imported: 1, importedEntries: [...] }`. Also used snake_case field names
instead of camelCase.

**Fix:** Updated R8a-R8c and R9a-R9b assertions to match current API response shape.

### Bug 8: Browser Phase Hang in CI
**Files:** `.github/workflows/ci.yml`
**Problem:** Three tests (email-auth, prefs-roundtrip, ai-badge-e2e) have interactive
browser phases that wait for a stop file. Without `MMGR_QA_NO_BROWSER=1`, CI hangs
for 10-20 minutes doing nothing.

**Fix:** Added `MMGR_QA_NO_BROWSER: 1` env var to all three CI steps.

### Bug 9: Phase 4 Rate Limiter Exhaustion
**File:** `tools/qa-email-auth.cjs`
**Problem:** Phase 4 shared Phase 3's wrangler without restarting. The accumulated
rate-limit counter from Phase 3's requests caused every Phase 4 request to return 429.

**Fix:** Added `await startWrangler('email')` before Phase 4 to restart wrangler with
a fresh rate limiter while keeping the same D1/R2 state.

## Key Learnings

1. **Column name mismatches are silent killers** — D1 throws on unknown columns, but
   the try/catch silently swallows it. Always cross-reference migration SQL with code.

2. **Session cookies need a jti for server-side revocation** — Without it, readSession
   skips the DB check, and password change/reset can't find sessions to revoke.

3. **RATE_LIMITER binding persists state on disk** — In miniflare, the binding stores
   rate-limit state via --persist-to. Removing it and using the in-memory fallback
   (which resets on process restart) is correct for CI testing.

4. **Interactive browser phases need MMGR_QA_NO_BROWSER=1** — Tests with stop-file
   waits will hang CI indefinitely without this env var.

5. **Test code drifts from API shape** — The changelog import API changed its response
   shape (imported as count, not array; camelCase fields), but the test still used
   the old shape. Always verify test assertions match the actual API response.
