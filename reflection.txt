THE SIGN-IN BUG (the real work)
The v521 fix let the FIRST refusal pass, which exposed the next gate in line.
js/mmgr-google-auth.js posted `freshIdNonce()` - the newest nonce the page
held - while the credential carries the nonce GIS had live when it composed the
token. initGIS() draws the button BEFORE fetchSignInNonce() resolves, and the
4-minute refresher moves the module's copy, so the two routinely disagree.
src/auth/google.js compares nonceClaim !== postNonce and answered 401 for a
genuine, Google-signed credential.

FIX (8e7cbcc)
- nonceOfIdToken() reads the claim out of the credential (base64url payload,
  TextDecoder). Not a trust decision: the Worker still validates with Google.
  That value is what travels.
- fetchSignInNonce() re-initialises AND redraws the GIS button when the nonce
  actually changes (redrawGisButton), so the next credential carries a live one
  - this matters when GOOGLE_NONCE_REQUIRED is turned on.
- A refusal on the nonce arm retries ONCE nonceless, the path the flag-off
  server already accepts; replay protection stays in the single-use row.
- The Worker's refusals carry a machine reason into console.warn
  (nonce_absent, nonce_mismatch, nonce_not_live, email_unverified, audience,
  tokeninfo_*) and still return the same generic 401 body. Before this, a live
  failure was a blind 401 and the only diagnosis method was guessing.

GATE (new, verified to bite)
tools/qa-google-nonce.cjs, 11 arms, ci.yml browser-calc, registry row CI.
It drives the REAL callback on about.html with a three-segment ID token whose
payload nonce differs from the nonce the page fetched (route-stubbed), then
asserts: the token's nonce is posted and the page's never is; a nonceless
credential posts no nonce key; a refused nonce yields exactly one nonceless
retry that signs in with no refusal line left behind; a double refusal states
the reason on the page; a changed nonce re-initialises and redraws the button;
zero page errors. Teeth proven by reverting js/mmgr-google-auth.js only and
re-running: 7 of 11 fail, and N3b reproduces the owner's exact string
("Google sign in did not finish. Try again, or use the email sign in below.").
