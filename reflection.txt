LESSONS
  - A NEW HARNESS'S FIRST CI RUN IS ITS REAL FIRST RUN. qa-code-names passed 26/26
    locally for days and failed the moment CI ran it, because locally Playwright's
    chromium exists (Windows cache) and in CI it never downloads. A browser harness
    must take its browser from the same place its siblings do.
  - WHEN CI STOPS, RUN EVERY STEP IT SKIPPED - again, and read what falls out. The
    steps after the qa-calc-assistant failure surfaced qa-consent's undocumented
    storage key, a defect no green gate was looking at.
  - RE-BASELINE THE ARM ONLY AFTER PROVING THE APP CHANGE WAS DELIBERATE. The
    calc-assistant border arm was wrong because the gold sweep had moved borders on
    purpose (contrast floor); the mutation proof (155/156) shows the new arm still
    bites.
  - A LIVE PROBE IS A CLAIM ABOUT PRODUCTION, AND ITS FIRST RUN TESTS THE PROBE.
    All six first-run failures were the script's bugs: a while-read subshell that
    emptied $HOME, a grep that cannot skip multi-line comment text, an expected
    count of 1 where the stylesheet has 2, a minified bundle where the identifier is
    renamed (the served SOURCE is the contract), the wrong page (the AI window lives
    on project.html), and an invented status code (403 has been the cloudForbidden
    contract since before this wave). Diagnose each against the source before
    believing any of them - and note Cloudflare injects an inline challenge script
    (__CF$cv$params/cdn-cgi) into every HTML response, so a CSP hash probe must skip
    edge-injected blocks or it reports phantom misses forever.
  - A GATE'S BAN LIST IS A CONTRACT WITH A DOCUMENTED SCOPE. The probe's orange scan
    failed on the amber ramp (#f59e0b/#d97706) until read against verify-gold: those
    are GOLD-AUDIT's documented "semantic status colours" keeps (amber means due
    soon; gold is identity), and the ban list is the nine retired brand-orange
    values. Scan with the gate's list, not with a guessed one.
