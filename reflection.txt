2. ADMIN HAMBURGER/SIDEBAR FIX (admin.html)
   ROOT CAUSE: Two separate bugs combined to break the admin sidebar:
   a) CSS CLASS MISMATCH: The admin's inline CSS used `body.sidebar-open .db-side` to
      reveal the sidebar, but the FOUC script and mmgr.css use `body.side-open`. On
      desktop, the FOUC script set `side-open` on body, but the CSS rules for the
      sidebar visibility checked `sidebar-open` (different class). The sidebar was
      translated to position but stayed `visibility:hidden`.
   b) CONFLICTING CLICK HANDLERS: admin.html had TWO document-level click listeners:
      - Line 1741: Rail navigation handler that called `closeAdminNav()` for ANY click
        inside #app-sidebar on an [data-action] element.
      - Line 1799: Action map handler that dispatched to `tglAdminNav()`.
      When clicking the close button (data-action="tglNav"), the first handler ran
      `closeAdminNav()` (removing both classes), then the second ran `tglAdminNav()`
      (toggling them back on). Net result: sidebar stayed open — the X never closed it.
   FIX:
   - Admin inline CSS changed from `body.sidebar-open` to `body.admin-page.side-open`
     matching the shared mmgr.css db-page pattern exactly.
   - `tglAdminNav()` simplified: now only toggles `side-open` (removed `sidebar-open`).
   - `closeAdminNav()` simplified: only removes `side-open`.
   - Rail click handler updated: skips `.db-side-close` button clicks and `tglNav` actions
     so the close button's own action handles its state without fighting.
   - All `sidebar-open` references in admin CSS removed.

3. ADMIN EMAIL AUTH VISIBILITY FIX (admin.html)
   - The second `mmgr:user-changed` listener at line ~1840 was always hiding
     `email-auth-block` and `google-signin-button` regardless of auth state.
   - Fixed to only hide when signed in (`signedIn = !!(e && e.detail)`).

4. DEMO PROJECT ISOLATION (admin.html, js/mmgr-cloud.js)
