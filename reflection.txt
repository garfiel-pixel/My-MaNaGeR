6. CSP HASH MANAGEMENT
   - The most common failure pattern: editing an inline <script> block in any
     HTML file changes its SHA-256 hash, which must be updated in BOTH
     worker.js INLINE_SCRIPT_HASHES and serve.cjs mirror. The hash is
     position-sensitive (must be in the same order as computed).
   - Also: serve.cjs must be RESTARTED after edits — a stale serve.cjs process
     serves old CSP headers, causing ALL inline scripts to be blocked with no
     visible error (functions become undefined).

=== FAILURES AND MISTAKES (LEARNED THE HARD WAY) ===

1. STALE SERVE.CJS PROCESS: After updating serve.cjs with new CSP hashes, the
   old process was still running. The verify script passed (it reads the file),
   but the live server served old headers. Chrome silently blocked ALL inline
   scripts. Functions like `handleSetupPassword`, `ADMIN_ACTION_MAP`, `projects`
   were all `undefined`. LESSON: ALWAYS restart serve.cjs after editing it.
   The verify script reads the file on disk — it does NOT check what the
   running process is serving.

2. DUPLICATE SEARCH BUTTONS: Added a search button to the Projects section
   header AND kept the existing header search icon. User explicitly said
   "You do not need two searches in one page." LESSON: check for existing
   functionality before adding new UI.

3. CSP HASH DRIFT: Every edit to an inline <script> block changes the hash.
   Forgot this multiple times. LESSON: automate hash regeneration — always
   recompute after ANY inline script edit.

4. CI TEST SELECTOR MISMATCH: The verify-controls-admin.cjs test expects
   specific CSS class names (.auth-bar, .rail-ctl-row) and DOM structure.
   When I rewrote the admin sidebar, I used different class names (db-ctl-row
   instead of rail-ctl-row, db-user instead of auth-bar). LESSON: always run
   the full CI battery locally before pushing — read the test expectations
   and match them.

5. DEMO_SEED CLEARED: I cleared the admin DEMO_SEED to empty array, but the
   CI test S3 expects at least one project row in the admin panel. LESSON:
   read CI test expectations before removing seed data.
