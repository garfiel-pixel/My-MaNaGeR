### 4. Fixes Applied This Session

#### Fix 1: D1 Migration Path (`--persist-to`)
**Problem:** `wrangler d1 migrations apply --local` stores the database in
`.wrangler/state/v3/d1/`, but `wrangler dev` with a fresh `.wrangler/tmp/dev-*`
creates a separate D1 instance. Tests got `no such table: cloud_projects`.

**Fix:** Both the migration command AND wrangler dev must use the same
`--persist-to /tmp/mmgr-wrangler-state` path. Verified this matches what
the CI workflow does.

#### Fix 2: Missing `ADMIN_CODE` in CI config
**Problem:** `wrangler.ci.jsonc` didn't define `ADMIN_CODE` as a var. The admin
endpoint returned 403 for all requests because `env.ADMIN_CODE` was undefined.

**Fix:** Added `"ADMIN_CODE": "QA-TEST-ADMIN"` to the `vars` section of
`wrangler.ci.jsonc`. The CI workflow also writes `.dev.vars` with the value.

#### Fix 3: Shared wrangler `BASE` URL override
**Problem:** Scripts that were updated with `externalWranglerGuard` to use the
shared wrangler still had `const BASE = 'http://127.0.0.1:' + PORT` hardcoded
to their own port (8794-8798). When using the shared wrangler on port 8787,
all API calls went to the wrong port.

**Fix:** Changed `const BASE` to `let BASE` and added:
```js
if (USE_EXTERNAL && process.env.WRANGLER_DEV_URL) BASE = process.env.WRANGLER_DEV_URL;
```
Applied to: ai-badge-e2e, t9-adoption.

#### Fix 4: Tests that CAN'T use shared wrangler — reverted
**Problem:** 6 scripts (reviews, rank9, t9, presence, prefs-roundtrip,
offline-copies) pass custom `--var GOOGLE_CLIENT_SECRET:X` to their wrangler.
Each test uses a different secret for session HMAC signing. The shared wrangler
doesn't have any of these secrets, so session cookies don't verify.

**Fix:** Reverted `externalWranglerGuard` and `stopWranglerIfLocal` from these
6 scripts. They start their own wrangler with their own secrets. Removed
`WRANGLER_DEV_URL` from their CI workflow steps.

#### Fix 5: Email auth — always own wrangler
**Problem:** Email auth needs custom vars (RESEND_API_KEY, LEMONSQUEEZY_*,
GOOGLE_CLIENT_SECRET) that the shared wrangler can't provide. The stub
server approach requires `RESEND_API_BASE` pointing to a local stub.

**Fix:** Reverted `externalWranglerGuard` from email-auth. It always starts
its own wrangler.

## Key Insight: Miniflare Proxy Objects

When `wrangler.dev` starts without a binding declared in config, miniflare still
creates a **JavaScript Proxy object** for it. This means:
- `if (!env.BINDING)` is ALWAYS truthy (Proxy is truthy)
- `env.BINDING.get(...)` triggers the proxy which may crash
- `env.BINDING.fetch(...)` triggers the proxy which may crash
- **Only `try/catch` around the actual call works**, not null checks

This was discovered in the previous session and remains the key finding for
writing resilient worker code.
